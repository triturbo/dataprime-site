Field notes

Network architecture

Distance sets the floor

Start with the propagation budget before tuning the code on either end.

Read note Close note on the latency floor

New York and London are about 5,570 km apart along a great circle. At a rounded 200,000 km/s in glass, a fibre that followed that line would take about 28 ms to carry a signal one way. Installed cable length, equipment and queueing add to that illustrative budget.

For an order path, trace the elapsed time from market-data arrival to the order leaving the gateway. Timestamp feed ingress, book update, decision and send. Compare spans on the same clock where possible. Across hosts, measure clock offset and include the uncertainty in the result.

A tail that grows in bursts points to a different investigation than a steady offset. Break down queue time and processing time under representative load before deciding where to optimise. Corning’s optical propagation analysis.

Market data

When a feed falls silent

Define what counts as a usable book during a quiet market, a sequence gap and a replay.

Read note Close note on market-data recovery

During a quiet market, track transport liveness and book completeness separately. Track the next expected sequence number for each feed session. On MoldUDP64, the heartbeat carries that sequence, so a receiver can detect a missing message between market updates. Nasdaq’s MoldUDP64 specification.

When a gap appears, mark the affected books as recovering and tell downstream consumers which decisions can proceed. Buffer live updates during replay. If the missing range has aged out and the venue supports sequenced snapshots, rebuild at the snapshot boundary and apply the contiguous updates that follow it.

Set the return-to-live test in advance. Require a contiguous sequence and a backlog within the freshness budget. Record the gap range, the recovery source and the time until the book was usable again.
